# Repair Prompt — Storage_url Cached Signed URL Policy

## Purpose
Define the lifecycle policy for the `storage_url` column in the `files` table: when it is set, when it is cleared, and what guarantees (if any) the cached URL provides.

## Audit Evidence
Source: `docs/10_EXTERNAL_SECURITY_AUDIT.md` — Item 12 (Medium).

Current schema: `storage_url TEXT` with comment "cached Signed URL (nullable)". ADR-016 says "Signed URLs generated at request time." Storing a time-limited Signed URL without an expiry field or refresh policy creates risk of expired or stale URLs.

## Mandatory Reading
- `docs/06_DATA_SCHEMA.md`
- `docs/09_DECISIONS.md` (ADR-016)

## Required User Decision, If Any
None — resolved. Per ADR-016 and ADR-017, `storage_url` should be **removed from the schema** and replaced with runtime-only Signed URL generation.

## Allowed Files
- `docs/06_DATA_SCHEMA.md`

## Forbidden Actions
- Do not modify application code.

## Required Changes
1. **Remove** the `storage_url TEXT` column from the `files` table definition in `docs/06_DATA_SCHEMA.md` — it is not stored in the database.
2. Replace it with a documentation note in the schema:
   ```sql
   -- File access is via runtime-generated Signed URLs only (see ADR-016/017).
   -- Use the Supabase Admin client to generate short-lived (5-minute TTL) Signed URLs
   -- from storage_path at request time. NEVER store or cache Signed URLs in the database.
   ```
3. Update the TypeScript `FileRecord` interface to remove `storage_url?: string`.
4. Document the Signed URL generation flow:
   - **Authenticated (admin) access**: Generated by Next.js API Route or server component using `supabase.storage.from('template-files').createSignedUrl(storage_path, 300)`.
   - **Public (share link) access**: Generated by API Route `GET /api/share/[token]/files/[fileId]/download` with 5-minute TTL (per ADR-017).
   - Never returned to client for caching/storage; generated fresh on each download request.

## Compatibility Requirements
- ADR-016: Signed URLs at request time, never stored.
- ADR-017: Public file access via API Route with Service Role, 5-minute TTL.
- Must not break the `files` table schema (removal of a nullable column is backward-compatible).

## Acceptance Criteria
- [ ] `storage_url` column is removed from `docs/06_DATA_SCHEMA.md`.
- [ ] A clear documentation note replaces it explaining the runtime Signed URL mechanism.
- [ ] TypeScript `FileRecord` interface no longer has `storage_url`.
- [ ] Both authenticated and public access flows document Signed URL generation.

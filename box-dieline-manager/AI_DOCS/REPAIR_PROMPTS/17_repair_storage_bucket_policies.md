# Repair Prompt — Storage Bucket Name, Path Structure, and RLS Undefined

## Purpose
Define the Supabase Storage bucket configuration: bucket name, folder path structure, Storage RLS policies, cleanup procedures, and consistency guarantees.

## Audit Evidence
Source: `docs/10_EXTERNAL_SECURITY_AUDIT.md` — Item 17 (Medium).

Current docs specify that Storage is private (Rule 8, ADR-016) and `storage_path` is stored in the `files` table, but do not define:
- Bucket name.
- Folder structure: `templates/{templateId}/{fileId}/{filename}` or similar.
- Storage RLS policies (`storage.objects` policies).
- Overwrite prevention.
- Cleanup on soft-delete or file deletion.
- Rollback procedure if upload succeeds but metadata insert fails.

## Required Changes
1. In `docs/05_TECH_SPEC.md`, add a Storage Configuration section:
   - **Bucket name:** `template-files` (locked).
   - **Visibility:** Private (no public access at bucket level).
   - **Path structure:** `templates/{templateId}/{fileId}/{original_filename}`.
   - **Overwrite prevention:** Use unique `fileId` (UUID) in path — never overwrite existing files.
2. In `docs/06_DATA_SCHEMA.md`, add Storage RLS policy section:
   - **`storage.objects` policies for authenticated admin:**
     ```sql
     CREATE POLICY "Admin can read template files"
       ON storage.objects FOR SELECT
       USING (
         auth.role() = 'authenticated'
         AND bucket_id = 'template-files'
       );

     CREATE POLICY "Admin can upload template files"
       ON storage.objects FOR INSERT
       WITH CHECK (
         auth.role() = 'authenticated'
         AND bucket_id = 'template-files'
       );

     CREATE POLICY "Admin can delete template files"
       ON storage.objects FOR DELETE
       USING (
         auth.role() = 'authenticated'
         AND bucket_id = 'template-files'
       );
     ```
   - **Public access:** No public RLS on `storage.objects` — public file access is ONLY via Signed URLs generated by API Route (per ADR-017).
3. Align with the upload contract (Repair Prompt 13):
   - Signed Upload URLs are used for upload (not direct Storage API from client).
   - Final path is set after metadata insert succeeds.
   - Orphan files are cleaned up per the contract (immediate delete on metadata failure + background cleanup).

## Compatibility Requirements
- ADR-004: Supabase Storage.
- ADR-016: Private buckets, Signed URLs only.
- ADR-017: Public access via API Route only; admin access via RLS + Signed URLs.
- Must not conflict with the upload contract in Repair Prompt 13.
